# 가이드 02 · 프레임 추출과 고르기

## 목표
- 업로드한 영상에서 FFmpeg로 1초에 1장씩 프레임을 뽑음
- 그중 **Jev에 보낼 프레임만 골라** 디스크에 남기고, 시각·장면 변화 점수를 DB에 저장함
- 1단계 두 번째 항목 "FFmpeg로 장면 변화가 큰 프레임만 추출해 저장". 다음 가이드(Jev 호출 서비스)가 여기서 저장한 프레임을 씀

## 완료 기준
- `.\gradlew.bat test` 통과 (새 테스트 8개 포함, 전체 13개)
- 서버를 띄우고 `P1.mp4`를 올린 뒤 프레임 추출 API를 부르면 `201 Created`와 프레임 16장 목록이 오고, `uploads/frames/{영상id}/`에 jpg 16장이 남음

## 만들 API
| 요청 | 설명 | 성공 | 실패 |
|---|---|---|---|
| `POST /api/videos/{videoId}/frames` | 프레임을 뽑고 골라서 저장 | 201 + 고른 프레임 목록 | 없는 영상 404, 이미 추출함 409 |
| `GET /api/videos/{videoId}/frames` | 저장한 프레임 목록 (시각 순) | 200 + 목록 | 없는 영상 404 |

응답 예시:
```json

```

## 1. 개념 먼저

### 1-1. 왜 프레임을 고르나
- Jev 비용은 **보내는 이미지 장수**에 거의 비례함 (요청 하나 약 2,800토큰 중 이미지가 96%, 결정 002)
- 실제 녹화본은 대부분 빈 매장임. 빈 화면을 보내지 않으면 비용과 시간이 크게 줄어듦
- 그렇다고 너무 많이 빼면 중요한 장면을 놓침. 이 둘 사이의 기준을 정하는 것이 이번 가이드의 핵심임

### 1-2. 장면 변화 점수 (scene score)
- FFmpeg가 프레임마다 "직전 프레임과 얼마나 다른가"를 0~1로 계산해 줌. 0이면 똑같고 1이면 완전히 다름
- 테스트 영상에서 잰 값 (1초 간격)
  - 빈 매장: 0.000 ~ 0.005
  - 사람이 걸어 들어옴: 0.03 ~ 0.13
  - **제자리에 서서 손만 움직임 (몰래 넣는 동작)**: 0.000 ~ 0.010 → 빈 매장과 거의 같음
- 화면 전체를 기준으로 계산해서, 화면에서 손이 차지하는 작은 부분이 바뀌어도 점수가 거의 오르지 않음

### 1-3. 그래서 "변화가 큰 프레임만"이 아니라 "움직임 주변을 통째로" 고름 (결정 003)
- 변화가 큰 프레임만 고르면(점수 > 0.01) 호출은 절반으로 줄지만, **유일한 진짜 "넣음" 프레임(P2 7초)을 포함해 중요한 프레임 16장을 버림**
- 대신 "점수가 0.005를 넘은 프레임이 있으면 그 **앞뒤 2초**를 모두 남김"으로 정함
  - 손님이 움직이다가 잠깐 멈춰 손만 쓰는 구간이 남음
  - 빈 매장이 2초 넘게 이어지는 구간만 빠짐
- 테스트 영상 8편 결과: 109장 → 105장. 중요 프레임 45장은 모두 남음
  - 이 영상들은 거의 내내 사람이 있어서 줄어든 양이 작음. 실제 녹화본에서는 훨씬 많이 줄어들 것으로 예상하고, 3단계에서 실제로 잼
- 기준값(0.005)과 앞뒤 초(2)는 설정 파일로 뺌. 매장마다 바꿀 수 있음

```
점수:  0    0    0    0    0.05  0    0    0    0    0    0
시각:  0초  1초  2초  3초  4초   5초  6초  7초  8초  9초  10초
고름:            ✔    ✔    ✔     ✔    ✔                    ← 4초의 앞뒤 2초
```

### 1-4. Java에서 외부 프로그램 실행하기 (ProcessBuilder)
- FFmpeg는 Java 라이브러리가 아니라 별도 프로그램임. 터미널에서 치던 명령을 Java가 대신 실행함
- `new ProcessBuilder("ffmpeg", "-i", "입력.mp4", ...)`: 명령과 인자를 **하나씩 따로** 넘김
  - 셸을 거치지 않아서 따옴표·띄어쓰기 처리가 필요 없고, 파일 이름에 이상한 문자가 있어도 명령이 바뀌지 않음 (명령어 주입 방지)
- `directory(폴더)`: 이 폴더에서 실행한 것처럼 함. 상대 경로로 쓴 출력 파일이 이 폴더에 생김
- `redirectErrorStream(true)`: 오류 출력(stderr)을 일반 출력(stdout)과 합침
- **출력을 반드시 읽어야 함**: 프로그램이 내보낸 글을 아무도 안 읽으면 운영체제 버퍼가 가득 차고, 프로그램이 "다 읽을 때까지" 멈춰서 영원히 안 끝남
- `waitFor()`: 프로그램이 끝날 때까지 기다리고 종료 코드를 돌려줌. 0이면 성공, 그 외는 실패

### 1-5. 이번에 쓰는 FFmpeg 명령
```
ffmpeg -i 영상.mp4 -vf "fps=1,scale='min(1280,iw)':-2,select='gte(scene,0)',metadata=print:key=lavfi.scene_score:file=scores.txt" -fps_mode passthrough -q:v 2 frame_%04d.jpg
```
| 부분 | 뜻 |
|---|---|
| `-vf "a,b,c"` | 영상 필터를 왼쪽부터 차례로 적용함 |
| `fps=1` | 1초에 1장만 남김 |
| `scale='min(1280,iw)':-2` | 가로가 1280보다 크면 1280으로 줄임. 세로(-2)는 비율에 맞춰 짝수로 정함. Jev 제한(1,568px)과 토큰 절약 |
| `select='gte(scene,0)'` | 점수가 0 이상인 프레임을 고름 = 전부 통과. 대신 이 필터가 프레임마다 scene 점수를 계산해 붙여 줌 |
| `metadata=print:...:file=scores.txt` | 프레임마다 시각과 scene 점수를 `scores.txt`에 씀 |
| `-fps_mode passthrough` | 프레임을 복제하거나 버리지 않고 필터가 내보낸 그대로 저장함 |
| `-q:v 2` | JPG 화질 (2~31, 작을수록 좋음) |
| `frame_%04d.jpg` | `frame_0001.jpg`, `frame_0002.jpg`… 네 자리 번호 |

`scores.txt` 내용 (프레임마다 두 줄):
```
frame:0    pts:0       pts_time:0
lavfi.scene_score=0.000000
frame:1    pts:1       pts_time:1
lavfi.scene_score=0.023417
```

### 1-6. 엔티티 연관관계: @ManyToOne
- 영상 하나에 프레임이 여러 장 → 프레임 쪽에서 보면 "여러 프레임이 영상 하나에 속함" = **ManyToOne**
- DB에는 `video_frames` 테이블에 `video_id` 칸(외래키)이 생기고, Java에서는 `frame.getVideo()`로 영상 객체를 얻음
- `fetch = FetchType.LAZY`: 프레임을 읽을 때 영상은 바로 읽지 않고, `getVideo()`로 실제로 쓸 때 읽음. 프레임 100장을 읽을 때 영상 조회가 같이 붙지 않게 함
- `optional = false`: 영상 없는 프레임은 없음 (DB에 NOT NULL)
- 영상 쪽(`Video`)에는 프레임 목록을 두지 않음. 필요할 때 Repository로 조회하면 충분하고, 양쪽에 두면 관리할 것이 늘어남 (단방향 연관관계)

### 1-7. 메서드 이름으로 쿼리 만들기 (Spring Data)
- `findByVideoIdOrderByTimeSecAsc(Long videoId)`: 메서드 이름을 읽어서 쿼리를 만들어 줌
  - `findBy` 조회 / `VideoId` = `video.id`가 같은 것 / `OrderByTimeSecAsc` 시각 오름차순
- `existsByVideoId(Long videoId)`: 하나라도 있으면 true
- 이름을 틀리게 쓰면(필드에 없는 이름) 서버가 뜰 때 바로 오류가 나서 실수를 빨리 알 수 있음

### 1-8. record를 "계산 결과 전달용"으로 쓰기
- `ExtractedFrame(fileName, timeSec, sceneScore)`: FFmpeg 결과를 다음 단계로 넘기는 값 묶음. DB에 저장하는 엔티티가 아님
- record는 같은 값이면 같은 객체로 봄(`equals`). 그래서 `Set`에 넣어 "고른 프레임인가"를 빠르게 확인할 수 있음

### 1-9. 상태 코드 409 Conflict
- 요청 자체는 맞지만 **현재 상태와 충돌**해서 처리할 수 없을 때 씀
- 이미 프레임을 뽑은 영상에 또 뽑으라고 하면 409로 막음 (같은 프레임이 두 번 저장되는 것을 방지)

### 1-10. 단위 테스트와 통합 테스트
| 테스트 | 무엇을 | 특징 |
|---|---|---|
| `FrameSelectorTest` | 고르는 규칙만 | Spring·DB·FFmpeg 없이 객체를 직접 만듦. 0.1초 안에 끝남 (단위 테스트) |
| `FrameExtractorTest` | FFmpeg 실행과 결과 읽기 | 진짜 FFmpeg를 실행함 |
| `VideoFrameControllerTest` | 업로드 → 추출 → 조회 전체 | Spring, DB, FFmpeg 모두 사용 (통합 테스트) |
- 규칙(고르기)을 FFmpeg 실행과 다른 클래스로 나눴기 때문에, 규칙을 FFmpeg 없이 여러 경우로 빠르게 시험할 수 있음
- 테스트 영상은 저장소에 넣지 않고 테스트할 때마다 FFmpeg로 만듦 (검은 화면 3초 → 흰 화면 3초, 3초에서 점수가 1에 가까움)
- `@TempDir`: 테스트마다 임시 폴더를 만들어 주고 끝나면 지움

### 3-2. `service/FrameExtractor.java`
```java
package com.mujinjigi.domain.video.service;

import java.io.IOException;
import java.io.UncheckedIOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

/**
 * FFmpeg로 영상에서 1초에 1장씩 프레임을 뽑고, 프레임마다 장면 변화 점수를 함께 구함
 */
@Component
public class FrameExtractor {

    private static final String SCORE_FILE = "scores.txt";

    // fps=1: 1초에 1장 / scale: 가로가 1280보다 크면 1280으로 줄임 (Jev 제한 1,568px, 토큰 절약)
    // select='gte(scene,0)': 모든 프레임을 통과시키면서 scene 점수를 계산하게 함
    // metadata=print: 프레임마다 시각과 scene 점수를 scores.txt에 씀
    private static final String FILTER = "fps=1,scale='min(1280,iw)':-2,select='gte(scene,0)',"
            + "metadata=print:key=lavfi.scene_score:file=" + SCORE_FILE;

    private final String ffmpegPath;

    public FrameExtractor(@Value("${app.ffmpeg.path}") String ffmpegPath) {
        this.ffmpegPath = ffmpegPath;
    }

    public List<ExtractedFrame> extract(Path videoPath, Path outputDir) {
        try {
            Files.createDirectories(outputDir);
            runFfmpeg(videoPath, outputDir);
            return readScores(outputDir.resolve(SCORE_FILE));
        } catch (IOException e) {
            throw new UncheckedIOException("프레임 추출 실패: " + videoPath, e);
        }
    }

    private void runFfmpeg(Path videoPath, Path outputDir) throws IOException {
        ProcessBuilder builder = new ProcessBuilder(
                ffmpegPath, "-hide_banner", "-loglevel", "error", "-y",
                "-i", videoPath.toAbsolutePath().toString(),
                "-vf", FILTER,
                "-fps_mode", "passthrough",
                "-q:v", "2",
                "frame_%04d.jpg");
        // scores.txt와 프레임 파일이 이 폴더에 생기도록 실행 폴더를 바꿈
        builder.directory(outputDir.toFile());
        // 오류 출력도 한 곳에서 읽음. 출력을 읽지 않으면 버퍼가 차서 FFmpeg가 멈출 수 있음
        builder.redirectErrorStream(true);

        Process process = builder.start();
        String output = new String(process.getInputStream().readAllBytes(), StandardCharsets.UTF_8);
        try {
            int exitCode = process.waitFor();
            if (exitCode != 0) {
                throw new IllegalStateException("FFmpeg 실패 (종료 코드 " + exitCode + "): " + output);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IllegalStateException("FFmpeg 실행 중 중단됨", e);
        }
    }

    // scores.txt는 프레임마다 두 줄씩 있음
    //   frame:0    pts:0       pts_time:0
    //   lavfi.scene_score=0.000000
    private List<ExtractedFrame> readScores(Path scoreFile) throws IOException {
        List<ExtractedFrame> frames = new ArrayList<>();
        double timeSec = 0;
        for (String line : Files.readAllLines(scoreFile)) {
            if (line.startsWith("frame:")) {
                timeSec = Double.parseDouble(line.substring(line.indexOf("pts_time:") + "pts_time:".length()).trim());
            } else if (line.startsWith("lavfi.scene_score=")) {
                double score = Double.parseDouble(line.substring("lavfi.scene_score=".length()));
                // 파일 번호는 1부터 시작함 (frame_0001.jpg가 첫 프레임)
                String fileName = String.format("frame_%04d.jpg", frames.size() + 1);
                frames.add(new ExtractedFrame(fileName, timeSec, score));
            }
        }
        return frames;
    }
}
```
- `-hide_banner -loglevel error`: 버전 정보와 진행 상황은 빼고 오류만 출력함. 실패했을 때 예외 메시지에 그 오류가 들어감
- `-y`: 같은 이름의 파일이 있으면 묻지 않고 덮어씀. 묻는 순간 FFmpeg가 입력을 기다리며 멈추기 때문에 꼭 필요함
- `videoPath.toAbsolutePath()`: 실행 폴더를 `outputDir`로 바꿨기 때문에, 영상 경로가 상대 경로면 엉뚱한 곳을 찾음. 절대 경로로 넘김
- `readAllBytes()`를 `waitFor()`보다 **먼저** 부름 (1-4의 버퍼 문제)
- `InterruptedException`을 잡으면 `Thread.currentThread().interrupt()`로 "중단 요청이 있었다"는 표시를 되살려 둠. 그냥 삼키면 위쪽 코드가 중단 요청을 모름 (관례)
- `readScores()`: `frame:` 줄에서 시각을 기억해 두고, 바로 다음 `lavfi.scene_score=` 줄에서 점수를 읽어 한 장을 완성함

### 3-3. `service/FrameSelector.java`
```java
package com.mujinjigi.domain.video.service;

import java.util.ArrayList;
import java.util.List;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

/**
 * Jev에 보낼 프레임을 고름. 움직임이 있는 프레임의 앞뒤 몇 초까지 남기고, 오래 조용한 구간은 뺌
 * 변화가 큰 프레임만 고르면 제자리에서 손만 움직이는 동작을 놓쳐서 이렇게 정함 (결정 003)
 */
@Component
public class FrameSelector {

    private final double sceneThreshold;
    private final int windowSeconds;

    public FrameSelector(@Value("${app.frame.scene-threshold}") double sceneThreshold,
                         @Value("${app.frame.window-seconds}") int windowSeconds) {
        this.sceneThreshold = sceneThreshold;
        this.windowSeconds = windowSeconds;
    }

    /**
     * @param frames 1초 간격으로 뽑은 프레임 (시각 순서)
     * @return 남길 프레임
     */
    public List<ExtractedFrame> select(List<ExtractedFrame> frames) {
        List<ExtractedFrame> selected = new ArrayList<>();
        for (int i = 0; i < frames.size(); i++) {
            if (hasMotionNear(frames, i)) {
                selected.add(frames.get(i));
            }
        }
        return selected;
    }

    // i번째 프레임의 앞뒤 windowSeconds장 안에 움직임이 있는 프레임이 있는가 (1초에 1장이라 장 수 = 초)
    private boolean hasMotionNear(List<ExtractedFrame> frames, int i) {
        int from = Math.max(0, i - windowSeconds);
        int to = Math.min(frames.size() - 1, i + windowSeconds);
        for (int j = from; j <= to; j++) {
            if (frames.get(j).sceneScore() > sceneThreshold) {
                return true;
            }
        }
        return false;
    }
}
```
- `Math.max(0, ...)`, `Math.min(size - 1, ...)`: 영상 처음과 끝에서 목록 범위를 벗어나지 않게 함 (벗어나면 `IndexOutOfBoundsException`)
- `@Value`로 받은 문자열 `"0.005"`, `"2"`는 Spring이 `double`, `int`로 바꿔 줌
- 생성자로 값을 받기 때문에 테스트에서는 `new FrameSelector(0.005, 2)`로 Spring 없이 만들 수 있음

package com.mujinjigi.domain.video.service;

import java.io.IOException;
import java.io.UncheckedIOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.web.server.ResponseStatusException;

import com.mujinjigi.domain.video.dto.VideoFrameResponse;
import com.mujinjigi.domain.video.entity.Video;
import com.mujinjigi.domain.video.entity.VideoFrame;
import com.mujinjigi.domain.video.repository.VideoFrameRepository;
import com.mujinjigi.domain.video.repository.VideoRepository;

/**
 * 영상에서 프레임을 뽑고, Jev에 보낼 프레임만 골라 저장함
 */
@Service
public class FrameService {

    private final VideoRepository videoRepository;
    private final VideoFrameRepository videoFrameRepository;
    private final VideoFileStorage videoFileStorage;
    private final FrameExtractor frameExtractor;
    private final FrameSelector frameSelector;
    private final Path frameDir;

    public FrameService(VideoRepository videoRepository,
                        VideoFrameRepository videoFrameRepository,
                        VideoFileStorage videoFileStorage,
                        FrameExtractor frameExtractor,
                        FrameSelector frameSelector,
                        @Value("${app.storage.frame-dir}") String frameDir) {
        this.videoRepository = videoRepository;
        this.videoFrameRepository = videoFrameRepository;
        this.videoFileStorage = videoFileStorage;
        this.frameExtractor = frameExtractor;
        this.frameSelector = frameSelector;
        this.frameDir = Path.of(frameDir).toAbsolutePath().normalize();
    }

    @Transactional
    public List<VideoFrameResponse> extract(Long videoId) {
        Video video = findVideo(videoId);
        if (videoFrameRepository.existsByVideoId(videoId)) {
            throw new ResponseStatusException(HttpStatus.CONFLICT, "이미 프레임을 추출한 영상임: " + videoId);
        }

        // 1. 1초에 1장씩 모두 뽑음 → 2. 보낼 프레임만 고름 → 3. 나머지 파일은 지움 → 4. 고른 프레임을 DB에 저장
        Path outputDir = frameDir.resolve(String.valueOf(videoId));
        List<ExtractedFrame> all = frameExtractor.extract(videoFileStorage.pathOf(video.getStoredName()), outputDir);
        List<ExtractedFrame> selected = frameSelector.select(all);
        deleteUnselected(all, selected, outputDir);

        return selected.stream()
                .map(frame -> videoFrameRepository.save(
                        new VideoFrame(video, frame.timeSec(), frame.sceneScore(), frame.fileName())))
                .map(VideoFrameResponse::from)
                .toList();
    }

    @Transactional(readOnly = true)
    public List<VideoFrameResponse> findAll(Long videoId) {
        findVideo(videoId);
        return videoFrameRepository.findByVideoIdOrderByTimeSecAsc(videoId).stream()
                .map(VideoFrameResponse::from)
                .toList();
    }

    private Video findVideo(Long videoId) {
        return videoRepository.findById(videoId)
                .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "영상이 없음: " + videoId));
    }

    private void deleteUnselected(List<ExtractedFrame> all, List<ExtractedFrame> selected, Path outputDir) {
        Set<ExtractedFrame> keep = new HashSet<>(selected);
        try {
            for (ExtractedFrame frame : all) {
                if (!keep.contains(frame)) {
                    Files.deleteIfExists(outputDir.resolve(frame.fileName()));
                }
            }
        } catch (IOException e) {
            throw new UncheckedIOException("고르지 않은 프레임 삭제 실패: " + outputDir, e);
        }
    }
}
```
- 영상마다 폴더를 나눔 (`uploads/frames/3/frame_0001.jpg`). 모든 영상의 프레임 이름이 `frame_0001.jpg`부터 시작해서, 한 폴더에 두면 서로 덮어씀
- `findAll()`에서 `findVideo(videoId)`의 결과를 쓰지 않는데도 부르는 이유: 없는 영상이면 404를 돌려주기 위함. 안 부르면 없는 영상도 빈 목록 `[]`과 200이 나가서, "프레임이 없음"과 "영상이 없음"을 구분할 수 없음
- `stream().map(...).map(...).toList()`: 고른 프레임을 하나씩 엔티티로 저장하고, 저장된 엔티티(id가 생김)를 응답 DTO로 바꿈
- `new HashSet<>(selected)`: `List.contains()`는 처음부터 끝까지 비교하지만 `Set.contains()`는 바로 찾음. 1시간 영상이면 3,600장이라 차이가 커짐

        // 3초에만 장면 변화 → 앞뒤 2초인 1~5초 5장 (0초는 빠짐)
        mockMvc.perform(post("/api/videos/{id}/frames", videoId))
                .andExpect(status().isCreated())
                .andExpect(jsonPath("$.length()").value(5))
                .andExpect(jsonPath("$[0].timeSec").value(1.0))
                .andExpect(jsonPath("$[4].timeSec").value(5.0));

        mockMvc.perform(get("/api/videos/{id}/frames", videoId))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.length()").value(5));
    }

    @Test
    void 같은_영상을_두_번_추출하면_409를_돌려준다() throws Exception {
        long videoId = uploadTestVideo();
        mockMvc.perform(post("/api/videos/{id}/frames", videoId)).andExpect(status().isCreated());

        mockMvc.perform(post("/api/videos/{id}/frames", videoId))
                .andExpect(status().isConflict());
    }

    @Test
    void 없는_영상의_프레임을_추출하면_404를_돌려준다() throws Exception {
        mockMvc.perform(post("/api/videos/{id}/frames", 999_999))
                .andExpect(status().isNotFound());
    }

    // 테스트 영상을 만들어 업로드 API로 올리고 영상 id를 돌려줌
    private long uploadTestVideo() throws Exception {
        Path video = TestVideos.blackThenWhite(tempDir);
        MockMultipartFile file = new MockMultipartFile("file", "test.mp4", "video/mp4", Files.readAllBytes(video));

        String body = mockMvc.perform(multipart("/api/videos").file(file))
                .andExpect(status().isCreated())
                .andReturn().getResponse().getContentAsString();
        // 응답 JSON에서 id만 꺼냄
        Number id = JsonPath.read(body, "$.id");
        return id.longValue();
    }
}
```
- 업로드도 실제 API(`POST /api/videos`)로 해서, 업로드 → 추출 → 조회가 이어지는지 함께 확인함
- `JsonPath.read(body, "$.id")`: 응답 문자열에서 `id`만 꺼냄. `jsonPath(...)` 검사와 같은 문법임
  - Spring Boot 4는 Jackson 3(`tools.jackson`)을 써서, 옛 자료의 `com.fasterxml.jackson.databind.ObjectMapper`는 import가 안 될 수 있음
- `$.length()`: 응답 배열의 길이
- 파일은 `build/test-uploads`, `build/test-frames`에 생김 (`gradlew clean`이면 지워짐). DB는 `@Transactional`로 되돌림

## 5. 알려진 한계 (면접에서 물어볼 만한 부분)
1. **추출이 요청 안에서 끝날 때까지 기다림 (동기)**
   - 20초 영상은 1초 안에 끝나지만, 1시간 영상이면 수십 초가 걸리고 그동안 HTTP 응답도, 트랜잭션의 DB 연결도 붙잡혀 있음
   - 2단계에서 분석을 작업(Job)으로 등록하고 바로 응답하는 비동기 방식으로 바꿈 (성능 기록 후보)
2. **중간에 실패하면 파일이 남음**: FFmpeg가 프레임을 쓴 뒤 DB 저장이 실패하면 DB는 롤백되지만 jpg는 남음 (가이드 01의 고아 파일 문제와 같음)
3. **사람이 오래 가만히 서 있으면 결국 빠짐**: scene 점수는 "직전 프레임과의 차이"라서, 2초 넘게 거의 안 움직이면 그 구간이 빠짐 (결정 003의 다음 단계: 빈 매장 기준 사진과 비교)
4. **1초에 1장이라 0.5초짜리 동작은 놓칠 수 있음**: 움직임이 있는 구간만 1초에 2~4장으로 촘촘히 뽑는 방법은 측정 후 정함
5. **세로 영상·작은 영상**: 가로 기준으로만 줄여서, 세로로 긴 영상은 높이가 1,568px를 넘을 수 있고, 280px보다 작은 영상은 Jev가 거부함
6. **영상인지 확인을 아직 안 함**: 가이드 01의 "확장자만 검사" 문제가 여기서 드러남. 영상이 아닌 파일이면 FFmpeg가 실패해서 500 오류가 남 → 업로드 때 FFprobe로 검사하는 것이 다음 개선 후보
