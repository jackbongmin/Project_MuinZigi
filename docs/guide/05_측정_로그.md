# 가이드 05 · 측정 로그

> **한 줄 요약**: **프레임 추출**(`FrameService`)과 **Jev 판단**(`JudgmentService`)이 한 번 돌 때마다 걸린 시간·프레임 수·Jev 호출 수·재시도 수·입력 토큰·설정값을 **영상과 연결해 DB(`measurement_logs`)**에 한 줄씩 남기고, **조회 API**로 꺼내 보는 기능 구현임

## 목표
- 성능 개선을 하기 전에 **지금 상태(Before)를 숫자로 남기는 장치**를 먼저 만듦 (handoff 8장 원칙: 바꾸기 전에 먼저 잼)
- 단계 한 번마다 걸린 시간, 프레임 수, Jev 호출·재시도 수, 입력 토큰, 그때 쓴 설정값을 저장함. 2단계 이후 그래프와 성능 기록은 이 로그로 만듦
- Jev가 재시도까지 실패해 502로 끝난 판단도 "실패"로 한 줄 남김. 실패·재시도가 얼마나 자주 생기는지 볼 수 있음
- 1단계 항목 "측정 로그 기록 시작 (8장 측정 로그)"에 해당함

## 완료 기준
- `.\gradlew.bat test` 통과 (새 테스트 4개 포함, 전체 26개)
- 서버를 띄우고 P1을 추출·판단한 뒤 `GET /api/videos/{id}/measurements`를 부르면 `FRAME_EXTRACTION` 1줄, `JUDGMENT` 1줄이 옴
- 판단에서 `jevCallCount`가 16, `inputTokens`가 약 44,848(16장 × 2,803)임

## 1. 개념 먼저

### 1-1. 왜 지금 만드나
- 앞으로 할 개선(활동 구간 줄이기, 이미지 크기 줄이기, 비동기 전환, 질문 수정)은 모두 "얼마나 빨라졌나·싸졌나"를 숫자로 말해야 포트폴리오가 됨
- **개선한 뒤에는 개선 전 상태를 다시 만들기 어려움.** 그래서 개선 작업보다 측정 장치가 먼저임
- 지금까지는 처리 시간과 토큰을 손으로 재서 문서에 적었음 (가이드 03: P1 16장 4.7초). 이제 서버가 매번 자동으로 남김

### 1-2. 무엇을 남기나 (handoff 8장 "측정 로그"와 비교)
| 8장 항목 | 이번에 남기는 칸 | 비고 |
|---|---|---|
| 작업 ID | 영상 id(`video_id`) + 단계(`step`) | 작업(Job)은 2단계에서 생김. 그때 작업 id 칸을 더함 |
| 영상 길이, 추출 프레임 수 | `extractedFrameCount`(1초에 1장 → 영상 길이(초)), `frameCount`(고른 수) | 추출 단계 |
| Jev 호출 수, 입력 토큰 수, 실패·재시도 수 | `jevCallCount`, `inputTokens`, `retryCount`, `success` | 판단 단계 |
| 단계별 처리 시간 | `elapsedMs` (단계마다 한 줄이라 단계별 시간이 됨) | 대조 단계는 2단계에서 추가 |
| 사용한 설정값 | `settings` (jsonb) | 추출: scene 기준값·앞뒤 초 / 판단: 질문 세트 버전 |

### 1-3. 한 줄 = 단계 한 번
- 영상 하나에 한 줄을 두고 칸을 채워 가는 방식도 있음. 하지만 판단은 **여러 번 불릴 수 있음** (가이드 04: 502로 멈추면 다시 불러 이어서 함)
- 그래서 **단계를 한 번 실행할 때마다 새 줄**을 추가함. 실패한 판단 1줄 + 이어서 한 판단 1줄처럼 실제로 일어난 일이 그대로 남음
- 같은 방식을 이미 씀: `jev_call_logs`는 시도 한 번마다 한 줄임. 측정 로그는 그보다 한 단계 큰 단위(단계 한 번)임

| 표 | 한 줄의 단위 | 쓰임 |
|---|---|---|
| `jev_call_logs` (가이드 04) | Jev 시도 한 번 | 판단이 이상할 때 원문 확인 |
| `measurement_logs` (이번) | 단계 실행 한 번 | 처리 시간·비용 비교, 그래프 |

### 1-4. 숫자를 더해 가는 엔티티
- 판단은 프레임 16장을 하나씩 처리함. 프레임마다 Jev 시도 수와 토큰이 생김
- 판단을 시작할 때 `MeasurementLog`를 하나 만들어 두고, 프레임을 처리할 때마다 `addJevCalls()`, `addJudgedFrame()`으로 **숫자를 더함.** 끝나면 `finish()`로 시간과 성공 여부를 채우고 저장함
- setter(`setJevCallCount()`) 대신 **뜻이 있는 메서드**를 둠. "재시도 수 = 시도 수 - 1"처럼 함께 바뀌어야 하는 값을 한 곳에서 계산하니 실수할 틈이 줄어듦
- 재시도 수 계산: 프레임 하나에 시도가 3번이면 재시도는 2번임. 그래서 `retryCount += attempts - 1`

### 1-5. `try` / `finally`로 실패도 남기기
```java
boolean success = false;
try {
    // 프레임마다 판단 → 중간에 Jev가 실패하면 502 예외가 던져짐
    success = true;
} finally {
    // 예외가 나도, 안 나도 반드시 실행됨
    log.finish(success, 걸린 시간);
    measurementLogRepository.save(log);
}
```
- `finally`는 `try` 안에서 예외가 나도 **반드시 실행됨.** 예외는 `finally`가 끝난 뒤 그대로 밖으로 나감 (502 응답은 그대로임)
- `success = true`는 `try`의 마지막 줄이라, 반복문이 끝까지 돌았을 때만 실행됨
- `catch`가 아닌 `finally`를 쓴 이유: 예외를 잡아서 처리할 생각이 없고, "끝날 때 기록만 하고 예외는 그대로 보냄"이 목적이라서임

**추출은 왜 실패를 안 남기나**
- `FrameService.extract()`에는 `@Transactional`이 있음. 중간에 FFmpeg가 실패하면 **그 트랜잭션에서 저장한 것이 모두 취소(롤백)**됨. 측정 로그도 같이 취소됨
- 판단은 `@Transactional`이 없고 `save()`마다 바로 저장해서(가이드 03) 실패해도 측정 로그가 남음
- 추출 실패까지 남기려면 측정 로그만 별도 트랜잭션으로 저장해야 함. 추출 실패는 아직 실제로 본 적이 없어서 이번에는 성공만 남김 (5장 한계 1)

### 1-6. `@Enumerated(EnumType.STRING)`: enum을 이름으로 저장
- `MeasurementStep`은 `FRAME_EXTRACTION`, `JUDGMENT` 두 값만 갖는 **enum**(정해진 값 목록)임. 문자열 `"JUDGMENT"`로 두면 오타(`"JUDGEMENT"`)를 컴파일러가 못 잡지만, enum은 잡음
- JPA는 기본으로 enum을 **순서 번호(0, 1)**로 저장함(`ORDINAL`). 2단계에서 `MATCHING`을 맨 앞에 넣으면 기존 0이 다른 뜻이 되어 기록이 망가짐
- `@Enumerated(EnumType.STRING)`을 붙이면 **이름(`"JUDGMENT"`)**으로 저장함. 값을 추가·재배치해도 안전하고 DB를 직접 봐도 읽힘

### 1-7. 설정값은 jsonb 한 칸 (`Map<String, Object>`)
- 추출은 scene 기준값·앞뒤 초, 판단은 질문 세트 버전을 씀. 2단계에서 의심도 기준값, 대조 허용 범위가 더 생김
- 설정마다 칸을 만들면 단계마다 비는 칸이 많고, 설정이 늘 때마다 테이블을 고쳐야 함 → 결정 004(판단 결과를 jsonb 한 칸에)와 같은 이유로 jsonb 한 칸에 담음
- `Map<String, Object>`로 둔 이유: 값이 숫자(`0.005`, `2`)도 있고 문자열(`"v2"`)도 있음. JSON에 숫자는 숫자로 남아야 나중에 그래프를 그릴 때 바로 씀
- 추출 설정값은 `FrameSelector`가 갖고 있음. 그래서 `FrameSelector`에 `settings()`를 더해 **값을 아는 클래스가 직접 알려 주게** 함. `FrameService`에 같은 `@Value`를 또 받으면 같은 설정을 두 곳에서 읽게 됨

### 1-8. 시간 재기
- `System.currentTimeMillis()`로 시작 시각을 받고, 끝날 때 다시 받아 뺌. `JevClient`가 시도 시간을 재는 방식(가이드 04)과 같음
- 판단 측정 시간은 **판단할 프레임을 고른 뒤부터** 잼. 영상 확인, 이미 판단한 프레임 조회는 빼고 "Jev 판단"에 걸린 시간만 봄
- 측정 로그를 저장하는 데 걸린 시간은 포함되지 않음 (저장 전에 `finish()`로 시간을 정함)

### 3-2. `analysis/entity/MeasurementLog.java`
```java
package com.mujinjigi.domain.analysis.entity;

import java.time.LocalDateTime;
import java.util.Map;

import org.hibernate.annotations.JdbcTypeCode;
import org.hibernate.type.SqlTypes;

import com.mujinjigi.domain.video.entity.Video;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.EnumType;
import jakarta.persistence.Enumerated;
import jakarta.persistence.FetchType;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.JoinColumn;
import jakarta.persistence.ManyToOne;
import jakarta.persistence.Table;

/**
 * 1단계 · 05 (측정 로그)
 * 처리 단계 한 번(프레임 추출 한 번, 판단 요청 한 번)의 측정값. 성능 개선 전후를 비교하고 그래프를 그릴 때 씀
 * 단계를 시작할 때 만들고, 진행하면서 숫자를 더하다가, 끝날 때 finish()로 걸린 시간과 성공 여부를 채움
 */
@Entity
@Table(name = "measurement_logs")
public class MeasurementLog {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "video_id")
    private Video video;

    // 어떤 단계의 측정인지. 순서 번호(0, 1)가 아니라 이름(JUDGMENT)으로 저장함
    @Enumerated(EnumType.STRING)
    @Column(nullable = false)
    private MeasurementStep step;

    // 끝까지 성공했는지. Jev가 재시도까지 실패하면 false로 남음
    @Column(nullable = false)
    private boolean success;

    @Column(nullable = false)
    private LocalDateTime startedAt;

    @Column(nullable = false)
    private long elapsedMs;

    // 1초에 1장씩 뽑은 전체 프레임 수 (= 영상 길이(초)). 프레임 추출에서만 채우고 판단에서는 비워 둠
    private Integer extractedFrameCount;

    // 이 단계에서 저장한 프레임 수. 추출: 고른 프레임 수 / 판단: 이번에 판단한 프레임 수
    @Column(nullable = false)
    private int frameCount;

    // Jev에 실제로 보낸 요청 수 (재시도 포함)
    @Column(nullable = false)
    private int jevCallCount;

    // 그중 재시도한 수
    @Column(nullable = false)
    private int retryCount;

    // 성공한 판단의 입력 토큰 합계 (과금 대상)
    @Column(nullable = false)
    private long inputTokens;

    // 이 측정에 쓴 설정값 (scene 기준값, 질문 세트 버전 등). 단계마다 다르고 2단계에서 늘어나서 jsonb 한 칸에 담음
    @JdbcTypeCode(SqlTypes.JSON)
    @Column(nullable = false, columnDefinition = "jsonb")
    private Map<String, Object> settings;

    protected MeasurementLog() {
    }

    // 단계를 시작할 때 만듦. 시작 시각은 지금으로 둠
    public MeasurementLog(Video video, MeasurementStep step, Map<String, Object> settings) {
        this.video = video;
        this.step = step;
        this.settings = settings;
        this.startedAt = LocalDateTime.now();
    }

    // 프레임 추출 결과를 기록함
    public void recordFrames(int extractedFrameCount, int selectedFrameCount) {
        this.extractedFrameCount = extractedFrameCount;
        this.frameCount = selectedFrameCount;
    }

    // 프레임 하나를 판단하며 Jev에 보낸 시도 수를 더함 (성공·실패 모두). 2번 이상이면 그만큼 재시도한 것임
    public void addJevCalls(int attempts) {
        this.jevCallCount += attempts;
        this.retryCount += attempts - 1;
    }

    // 판단에 성공한 프레임 하나를 더함
    public void addJudgedFrame(int inputTokens) {
        this.frameCount++;
        this.inputTokens += inputTokens;
    }

    // 단계가 끝났을 때 부름
    public void finish(boolean success, long elapsedMs) {
        this.success = success;
        this.elapsedMs = elapsedMs;
    }

    public Long getId() {
        return id;
    }

    public MeasurementStep getStep() {
        return step;
    }

    public boolean isSuccess() {
        return success;
    }

    public LocalDateTime getStartedAt() {
        return startedAt;
    }

    public long getElapsedMs() {
        return elapsedMs;
    }

    public Integer getExtractedFrameCount() {
        return extractedFrameCount;
    }

    public int getFrameCount() {
        return frameCount;
    }

    public int getJevCallCount() {
        return jevCallCount;
    }

    public int getRetryCount() {
        return retryCount;
    }

    public long getInputTokens() {
        return inputTokens;
    }

    public Map<String, Object> getSettings() {
        return settings;
    }
}
```
- `extractedFrameCount`만 `Integer`(객체)이고 나머지 숫자는 `int`/`long`임. 판단 단계에는 이 값이 **없음**을 `null`로 나타내려고 함. `int`면 0과 "없음"을 구분할 수 없음
- `frameCount`, `jevCallCount` 등은 `int` 기본값이 0이라 생성자에서 따로 0을 넣지 않음
- `video`는 `LAZY`임. 조회 응답에 영상 정보를 쓰지 않아서 영상을 따로 읽는 쿼리가 나가지 않음 (N+1 없음)

```java
package com.mujinjigi.domain.video.service;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

/**
 * 1단계 · 02 (프레임 추출과 고르기)
 * 1단계 · 05 (settings 추가)
 * Jev에 보낼 프레임을 고름. 움직밍이 있는 프레임의 앞뒤 몇 초까지 남기고, 오래 조용한 구간은 뺌
 * 변화가 큰 프레임만 고르면 제자리에서 손만 움직이는 동작을 노려서 이렇게 정함
 */

@Component
public class FrameSelector {

    private final double sceneThreshold;
    private final int windowSeconds;

    public FrameSelector(@Value("${app.frame.scene-threshold}") double sceneThreshold,
                         @Value("${app.frame.window-seconds}") int windowSeconds) {
        this.sceneThreshold = sceneThreshold;
        this.windowSeconds = windowSeconds;
    }

    // 고르기에 쓴 설정값. 측정 로그에 같이 남겨서 설정을 바꾼 전후를 비교할 수 있게 함
    public Map<String, Object> settings() {
        return Map.of("sceneThreshold", sceneThreshold, "windowSeconds", windowSeconds);
    }

    /**
     * @param frames 1초 간격으로 뽑은 프레임(시각 순서)
     * @return 남길 프레임
     */
    public List<ExtractedFrame> select(List<ExtractedFrame> frames) {
        List<ExtractedFrame> selected = new ArrayList<>();
        for (int i = 0; i < frames.size(); i++){
            if(hasMotionNear(frames, i)){
                selected.add(frames.get(i));
            }
        }
        return selected;
    }

    /**
     * i번째 프레임의 앞뒤 windowSeconds장 안에 움직임이 있는 프레임이 있는가 (1초에 1장이라 장 수 = 초)
     */
    private boolean hasMotionNear(List<ExtractedFrame> frames, int i ) {
        int from = Math.max(0, i - windowSeconds);
        int to = Math.min(frames.size()-1, i + windowSeconds);
        for(int j = from; j<=to; j++) {
            if(frames.get(j).sceneScore() > sceneThreshold){
                return true;
            }
        }
        return false;
    }
}
```
- 바뀐 곳: `settings()` 메서드와 `Map` import, 클래스 주석 둘째 줄
- `Map.of(키, 값, 키, 값)`은 바꿀 수 없는 Map을 만듦. `double`, `int` 값은 자동으로 `Double`, `Integer` 객체로 바뀌어 들어감

/**
 * 1단계 · 02 (프레임 추출과 고르기)
 * 1단계 · 05 (추출 측정 로그 저장)
 * 영상에서 프레임을 뽑고, Jev에 보낼 프레임만 골라 저장함
 */
@Service
public class FrameService {

    private final VideoRepository videoRepository;
    private final VideoFrameRepository videoFrameRepository;
    private final MeasurementLogRepository measurementLogRepository;
    private final VideoFileStorage videoFileStorage;
    private final FrameExtractor frameExtractor;
    private final FrameSelector frameSelector;
    private final Path frameDir;

    public FrameService(VideoRepository videoRepository,
                        VideoFrameRepository videoFrameRepository,
                        MeasurementLogRepository measurementLogRepository,
                        VideoFileStorage videoFileStorage,
                        FrameExtractor frameExtractor,
                        FrameSelector frameSelector,
                        @Value("${app.storage.frame-dir}") String frameDir) {
        this.videoRepository = videoRepository;
        this.videoFrameRepository = videoFrameRepository;
        this.measurementLogRepository = measurementLogRepository;
        this.videoFileStorage = videoFileStorage;
        this.frameExtractor = frameExtractor;
        this.frameSelector = frameSelector;
        this.frameDir = Path.of(frameDir).toAbsolutePath().normalize();
    }

    @Transactional
    public List<VideoFrameResponse> extract(Long videoId) {
        Video video = findVideo(videoId);
        if (videoFrameRepository.existsByVideoId(videoId)) {
            throw new ResponseStatusException(HttpStatus.CONFLICT, "이미 프레임을 추출한 영상임: " + videoId);
        }

        long start = System.currentTimeMillis();
        MeasurementLog log = new MeasurementLog(video, MeasurementStep.FRAME_EXTRACTION, frameSelector.settings());

        // 1. 1초에 1장씩 모두 뽑음 → 2. 보낼 프레임만 고름 → 3. 나머지 파일은 지움 → 4. 고른 프레임을 DB에 저장
        Path outputDir = frameDir.resolve(String.valueOf(videoId));
        List<ExtractedFrame> all = frameExtractor.extract(videoFileStorage.pathOf(video.getStoredName()), outputDir);
        List<ExtractedFrame> selected = frameSelector.select(all);
        deleteUnselected(all, selected, outputDir);

        List<VideoFrameResponse> responses = selected.stream()
                .map(frame -> videoFrameRepository.save(
                        new VideoFrame(video, frame.timeSec(), frame.sceneScore(), frame.fileName())))
                .map(VideoFrameResponse::from)
                .toList();

        // 5. 측정 로그 저장. 실패하면 트랜잭션이 통째로 취소되므로 성공한 추출만 남음
        log.recordFrames(all.size(), selected.size());
        log.finish(true, System.currentTimeMillis() - start);
        measurementLogRepository.save(log);
        return responses;
    }

    @Transactional(readOnly = true)
    public List<VideoFrameResponse> findAll(Long videoId) {
        findVideo(videoId);
        return videoFrameRepository.findByVideoIdOrderByTimeSecAsc(videoId).stream()
                .map(VideoFrameResponse::from)
                .toList();
    }

    // 프레임 이미지 파일의 실제 경로(Jev에 보낼 때 씀) 프레임 폴더 위치는 이 클래스만 알고있음.
    public Path imagePath(Long videoId, String fileName) {
        return frameDir.resolve(String.valueOf(videoId)).resolve(fileName);
    }

    private Video findVideo(Long videoId) {
        return videoRepository.findById(videoId)
                .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "영상이 없음: " + videoId));
    }

    private void deleteUnselected(List<ExtractedFrame> all, List<ExtractedFrame> selected, Path outputDir) {
        Set<ExtractedFrame> keep = new HashSet<>(selected);
        try {
            for (ExtractedFrame frame : all) {
                if (!keep.contains(frame)) {
                    Files.deleteIfExists(outputDir.resolve(frame.fileName()));
                }
            }
        } catch (IOException e) {
            throw new UncheckedIOException("고르지 않은 프레임 삭제 실패: " + outputDir, e);
        }
    }
}

- 전에는 `return selected.stream()...`으로 바로 돌려줬음. 측정 로그를 저장한 뒤 돌려주려고 결과를 `responses` 변수에 먼저 담음

 * 1단계 · 04 (Jev 호출 기록 저장, 실패 시 502)
 * 1단계 · 05 (판단 측정 로그 저장)
 * 저장된 프레임을 Jev에 보내 판단 결과를 저장함

@Service
public class JudgmentService {

    private final VideoRepository videoRepository;
    private final VideoFrameRepository videoFrameRepository;
    private final FrameJudgmentRepository frameJudgmentRepository;
    private final JevCallLogRepository jevCallLogRepository;
    private final MeasurementLogRepository measurementLogRepository;
    private final FrameService frameService;
    private final JevClient jevClient;

    public JudgmentService(VideoRepository videoRepository,
                           VideoFrameRepository videoFrameRepository,
                           FrameJudgmentRepository frameJudgmentRepository,
                           JevCallLogRepository jevCallLogRepository,
                           MeasurementLogRepository measurementLogRepository,
                           FrameService frameService,
                           JevClient jevClient) {
        this.videoRepository = videoRepository;
        this.videoFrameRepository = videoFrameRepository;
        this.frameJudgmentRepository = frameJudgmentRepository;
        this.jevCallLogRepository = jevCallLogRepository;
        this.measurementLogRepository = measurementLogRepository;
        this.frameService = frameService;
        this.jevClient = jevClient;
    }

    // @Transactional을 붙이지 않음.
    // Jev 호출(프레임당 약 1초)을 하는 동안 DB 연결을 붙잡지 않으려고 프레임 하나를 판단할 때마다 save()로 바로 저장함
    // (save()는 그 자체로 짧은 트랜잭션)
    public List<FrameJudgmentResponse> judge(Long videoId) {
        Video video = findVideo(videoId);
        List<VideoFrame> frames = videoFrameRepository.findByVideoIdOrderByTimeSecAsc(videoId);
        if (frames.isEmpty()) {
            throw new ResponseStatusException(HttpStatus.CONFLICT, "프레임을 먼저 추출해야 함: " + videoId);
        }

        Set<Long> judgedFrameIds = frameJudgmentRepository.findAllWithFrame(videoId, FrameQuestions.VERSION).stream()
                .map(judgment -> judgment.getFrame().getId())
                .collect(Collectors.toSet());

        long start = System.currentTimeMillis();
        MeasurementLog log = new MeasurementLog(video, MeasurementStep.JUDGMENT,
                Map.of("questionSetVersion", FrameQuestions.VERSION));
        boolean success = false;
        try {
            for (VideoFrame frame : frames) {
                if (!judgedFrameIds.contains(frame.getId())) {
                    frameJudgmentRepository.save(judgeOne(videoId, frame, log));
                }
            }
            success = true;
        } finally {
            // 중간에 502로 끝나도 실행됨. 실패한 판단도 몇 번 시도했는지 남기려고 finally에 둠
            log.finish(success, System.currentTimeMillis() - start);
            measurementLogRepository.save(log);
        }
        return findAll(videoId);
    }

    public List<FrameJudgmentResponse> findAll(Long videoId) {
        findVideo(videoId);
        return frameJudgmentRepository.findAllWithFrame(videoId, FrameQuestions.VERSION).stream()
                .map(FrameJudgmentResponse::from)
                .toList();
    }


    private FrameJudgment judgeOne(Long videoId, VideoFrame frame, MeasurementLog log) {
        byte[] image = readImage(videoId, frame);
        JevResult result;
        try {
            result = jevClient.askYesNo(image, "jpg", FrameQuestions.QUESTIONS);
        } catch (JevCallException e) {
            // 재시도까지 실패함. 실패한 시도도 기록으로 남기고, 외부 서버 문제라는 뜻으로 502를 돌려줌
            // 이미 판단한 프레임은 저장돼 있어서, 다시 부르면 남은 프레임부터 이어서 판단함
            saveCallLogs(frame, e.getRequestBody(), e.getAttempts());
            log.addJevCalls(e.getAttempts().size());
            throw new ResponseStatusException(HttpStatus.BAD_GATEWAY,
                    e.getMessage() + " (프레임 " + frame.getTimeSec() + "초)", e);
        }
        saveCallLogs(frame, result.requestBody(), result.attempts());
        JevResponse response = result.response();
        log.addJevCalls(result.attempts().size());
        log.addJudgedFrame(response.usage().inputTokens());

        // 응답 형식(Answer 객체)을 그대로 저장하지 않고, 질문 이름 → 확률만 꺼내서 저장함
        Map<String, Double> answers = new LinkedHashMap<>();
        response.answers().forEach((name, answer) -> answers.put(name, answer.noul()));

        return new FrameJudgment(frame, FrameQuestions.VERSION, response.model(),
                response.usage().inputTokens(), answers);
    }


    // 시도마다 한 줄씩 저장함 (재시도했으면 여러 줄)
    private void saveCallLogs(VideoFrame frame, String requestBody, List<JevCallAttempt> attempts) {
        jevCallLogRepository.saveAll(attempts.stream()
                .map(attempt -> new JevCallLog(frame, requestBody, attempt))
                .toList());
    }

    private byte[] readImage(Long videoId, VideoFrame frame) {
        try {
            return Files.readAllBytes(frameService.imagePath(videoId, frame.getFileName()));
        } catch (IOException e) {
            throw new UncheckedIOException("프레임 이미지를 읽지 못함: " + frame.getFileName(), e);
        }
    }

    private Video findVideo(Long videoId) {
        return videoRepository.findById(videoId)
                .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "영상이 없음: " + videoId));
    }
}

## 5. 알려진 한계 (면접에서 물어볼 만한 부분)
1. **추출 실패는 남지 않음**: `extract()`의 트랜잭션이 롤백되면 측정 로그도 같이 취소됨 (1-5). 남기려면 측정 로그 저장만 새 트랜잭션(`REQUIRES_NEW`)으로 분리해야 함
2. **서버가 판단 도중 꺼지면 측정 로그가 안 남음**: `finally`는 예외에는 실행되지만 프로세스가 죽으면 실행되지 않음. 시작할 때 먼저 저장하고 끝날 때 고치는 방식이면 "끝나지 않은 측정"도 보이지만, 지금은 단순하게 끝날 때 한 번만 저장함
3. **측정 코드가 업무 코드 사이에 섞여 있음**: `FrameService`, `JudgmentService`에 시간 재기와 숫자 더하기가 들어감. 단계가 늘면 AOP(메서드 앞뒤에 공통 코드를 끼우는 방식)나 작업(Job) 쪽으로 옮기는 것을 생각할 수 있음. 지금은 단계가 둘뿐이라 읽기 쉬운 쪽을 고름
4. **벽시계 시간으로 잼**: `currentTimeMillis()`는 PC 시계가 바뀌면 같이 바뀜. 몇 초 단위 측정에서는 문제가 안 되지만, 정밀한 측정에는 `System.nanoTime()`을 씀
5. **한 번 측정은 흔들림**: Jev 응답 시간은 호출마다 다름. 개선 전후를 비교할 때는 같은 영상으로 여러 번(예: 3번) 재서 평균·중앙값을 씀 (handoff 7장 측정 원칙)
