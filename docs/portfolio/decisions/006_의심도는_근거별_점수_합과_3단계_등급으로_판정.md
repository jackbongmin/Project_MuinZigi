# [결정] 의심도는 근거별 점수의 합으로 계산하고, 방문 단위로 3단계 등급을 매김

## 상황
- 2단계에서 영상과 결제 CSV를 넣으면 의심 장면을 만들어야 함. 그 전에 **무엇을 단위로, 어떤 계산으로, 어디부터 의심으로 볼지**를 정해야 판정 로직(순수 Java)과 단위 테스트의 경계값이 정해짐
- 결정 001에서 판정의 주 근거는 진열대 전후 비교(사라진 상품 vs 결제), 행동 판단(넣음)은 보조 근거로 정함
- 1단계까지는 프레임마다 판단만 있고, "손님 한 명"이라는 단위가 없음
- 2단계 계획을 짜면서 사용자가 두 가지를 추가로 요구함
  - 범인을 알아볼 수 있게 **얼굴이 잘 나온 장면**을 저장해야 함
  - **같은 상품 10개를 집고 8개만 결제**하는 경우도 잡아야 함

## 선택지 1 · 판정 단위 (방문을 어떻게 나눌까)
| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 사람 판단 연속 구간** | 이미 저장하는 `person` 확률을 그대로 씀. 추가 Jev 호출 없음 | 사람이 잠깐 가려지면 방문이 끊길 수 있음 → 끊김 허용 시간을 둠 |
| B. 활동 구간 = 방문 | 가장 단순함 (가이드 02 결과 그대로) | 손님이 가만히 서 있으면 scene 점수가 낮아 방문이 끊김. 화면 전체 기준이라 사람과 무관한 변화도 섞임 |

## 선택지 2 · 의심도 계산
| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 근거별 점수의 합 (0~1)** | 근거마다 가중치를 설정으로 빼서 바꿔 가며 오탐률을 잴 수 있음. 경계값 단위 테스트가 쉬움 | 가중치를 처음엔 근거 없이 정함 → 3단계 정확도 측정으로 조정 |
| B. 조건별 등급 표 | 숫자가 없어 읽기 쉬움 | 기준을 조금씩 옮겨 가며 측정하기 어려움. 근거가 늘면 표가 커짐 |

## 선택지 3 · 의심 등급
| 방법 | 장점 | 단점 |
|---|---|---|
| A. 높음·중간 2단계 | 점주가 볼 목록이 짧음 | 근거가 약한 방문은 아예 남지 않아 나중에 확인할 수 없음 |
| **B. 높음·중간·낮음 3단계** | 놓침을 줄임(목표 놓침 0건). 점주는 높음부터 보면 됨 | 목록이 길어짐 → 화면에서 등급으로 거름 |

## 결정
- **판정 단위는 방문**이고, 방문은 **사람 판단 연속 구간**(선택지 1-A)으로 나눔
  - `person` 확률이 판정 기준(0.5) 이상인 프레임을 시간순으로 이어 붙임
  - 사람이 **5초(설정) 이상** 안 보이면 방문이 끝남. 활동 구간 밖(프레임이 없는 시간)도 안 보인 것으로 봄
- **의심도 = 진열대 근거 + 행동 근거** (선택지 2-A, 가중치는 설정)
  | 근거 | 점수 | 조건 |
  |---|---|---|
  | 진열대 근거 | 0.7 | 방문 동안 사라진 상품이 결제된 상품보다 많음 |
  | 행동 근거 | 0 ~ 0.3 | 방문 안 프레임의 `putting_in_bag` 최대 확률 × 0.3 |
  - 진열대가 가려져 비교할 수 없으면 진열대 근거는 0이고 행동 근거만 남음. 그래서 행동만으로는 "중간"까지만 올라감 (결정 001: 넣는 장면은 필수 조건이 아님)
- **등급 3단계** (선택지 3-B, 기준값은 설정)
  | 등급 | 의심도 | 뜻 |
  |---|---|---|
  | 높음 | 0.7 이상 | 결제보다 많이 사라짐 (+ 행동 근거) |
  | 중간 | 0.2 이상 | 진열대 근거 없이 넣는 동작이 강하게 보임 (넣음 확률 약 0.67 이상) |
  | 낮음 | 0.1 이상 | 넣는 동작이 약하게 보임 (넣음 확률 약 0.33 이상) |
  | (저장 안 함) | 0.1 미만 | 정상 방문 |
  - 처음에는 중간 기준을 0.3으로 잡았으나, 행동 근거 최대치가 0.3이라 넣음 확률이 정확히 1.0일 때만 중간이 되는 문제가 있어 0.2로 내림
- **개수 문제**(같은 상품 10개 중 8개 결제)는 진열대 비교 단계에서 실험으로 정함
  - 지금 설계(칸마다 사라졌나 예/아니오)로는 같은 상품 여러 개를 못 셈
  - 칸을 잘라 Jev에 전후 개수를 묻는 정확도를 먼저 재고, 칸을 자리 단위로 쪼갤지 / 개수 의심을 의심도에만 반영할지 결정 기록으로 남김
- **얼굴 캡처**는 의심 장면의 증거로 저장함
  - 질문 세트에 "얼굴이 정면으로 또렷하게 보이나"를 더해, 방문 안에서 확률이 가장 높은 프레임을 고름. 이미지 한 장에 질문을 하나 더하는 것이라 추가 호출이 없음 (토큰 증가는 측정해서 기록)
  - **얼굴 인식(누구인지 맞추기)은 하지 않음.** 신원 판단은 점주·경찰이 사람 눈으로 함. 얼굴로 같은 사람을 찾는 기능(재방문자 연결)도 넣지 않음
  - 얼굴이 담긴 캡처는 개인정보이므로 보관 기간(기본 30일, 설정)을 두고, 점주만 볼 수 있게 함 (권한은 3단계 로그인 후)

## 이유
- 진열대 근거 하나만으로 "높음"이 되게 가중치를 잡음. 손이 가려져도 상품이 사라졌으면 놓치지 않는 것이 결정 001의 핵심이기 때문임
- 행동 근거의 최대치를 0.3으로 둔 이유: 자기 물건을 가방에 넣는 장면(N5)이 넣음 확률을 높게 받을 수 있음. 행동만으로 "높음"이 되면 오탐이 늘어남 (0단계 측정)
- 가중치·기준값을 모두 설정으로 뺀 이유: 3단계에서 정답표 대비 오탐률을 재며 조정하고, 바꿀 때마다 전후를 기록하기 위함 (7장 측정 원칙)
- 낮음까지 저장하는 이유: 목표가 놓침 0건임. 저장해 두면 점주가 놓친 사건을 나중에 찾을 수 있음

## 한계
- 가중치(0.7, 0.3)와 등급 기준(0.7, 0.2, 0.1)은 측정 근거 없이 정한 첫 값임. 3단계 정확도 측정에서 바꿀 가능성이 큼
- 방문 끊김 허용 5초도 첫 값임. 손님 여러 명이 연달아 들어오면 방문 둘이 하나로 합쳐질 수 있음 (7장 운영 환경 차이). 합쳐졌을 때 다른 손님의 결제가 도난을 가리는 문제와 처리 방식은 결정 007
- 테스트 영상은 두 가지를 씀: 기능 개발은 AI 생성 영상, 개수 실험과 2단계 완료 확인은 직접 촬영 영상 (AI 영상은 상품이 실제로 사라지지 않는 문제가 있었음)
