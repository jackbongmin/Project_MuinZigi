# [결정] 여러 명이 한 방문으로 합쳐지면, 결제가 도난을 가릴 수 있을 때만 "여러 명" 표시와 함께 낮음으로 남김

- 작성일: 2026-11-12 (가이드 08 방문 나누기 중)

## 상황
- 방문은 프레임마다 "사람이 있나(`person`)"만 보고 나눔 (결정 006, 가이드 08). 누가 몇 명인지는 모름
- 손님이 겹쳐 있거나 5초 안에 이어서 들어오면 **여러 명이 방문 하나로 합쳐짐**
- 사용자가 "손님 A, B, C가 각자 인식되나, 여러 명이 한 화면에 잡히면 체크되나"를 물어 확인한 결과, 합쳐질 때 **놓침**이 생길 수 있음
  - 예: A가 콜라를 가져가고 B가 콜라를 결제함 → 진열대 칸 기준으로 "콜라 사라짐, 콜라 결제됨"이라 정상으로 끝남
  - 의심 장면이 나와도 얼굴 캡처가 결제한 B의 얼굴일 수 있음
- 처음 안(여러 명이면 모두 "확인 필요")은 사용자가 **피로도 문제**를 지적함. 일행이 같이 와서 한 명이 계산하는 흔한 경우까지 모두 표시됨

## 선택지
| 방법 | 장점 | 단점 |
|---|---|---|
| A. 여러 명이면 모두 낮음 이상 | 단순함. 놓침 없음 | 일행 방문마다 뜸 → 점주 피로도가 커지고 목록을 안 보게 됨 |
| **B. 여러 명이면서 결제가 도난을 가릴 수 있을 때만 낮음** | 문제가 생길 수 있는 경우만 표시함. 일행 계산·아무것도 안 가져간 경우는 정상 | 조건이 개수 실험 결과에 달려 있음 |
| C. 사람 추적 (YOLO + 추적기로 사람마다 번호) | 실제로 A/B/C를 구분함 | Python 모델 서버가 필요함(기술 스택 변경). 1초 1장이라 추적이 자주 끊김. 범위를 넘음 |
| D. 생김새·얼굴로 같은 사람 찾기 | 사람별 구분 | 결정 006에서 개인정보 때문에 하지 않기로 함 |

## 결정과 이유
- **B를 고름.** 여러 명 방문에서 합쳐져서 실제로 문제가 되는 경우는 하나뿐임

  | 여러 명 방문에서 | 합쳐져서 생기는 문제 | 처리 |
  |---|---|---|
  | 사라진 상품이 없음 | 없음 | 정상 |
  | 사라진 수 > 결제 수 | 없음 (이미 높음) | 결정 006대로 |
  | 사라진 상품과 결제가 개수까지 맞음 (일행 중 한 명이 계산) | 없음 | 정상 |
  | **사라진 칸이 결제로 덮였는데 개수를 확인할 수 없음** | 다른 손님의 결제가 도난을 가릴 수 있음 | **낮음 + "여러 명" 표시** |

- "여러 명인가"는 질문 세트에 "사람이 두 명 이상 보이나"를 더해 알아냄. 2단계에서 얼굴 질문을 넣을 때 **같이 넣어 질문 세트 버전을 한 번만 올림**(v2 → v3). 이미지 한 장에 질문 하나가 느는 것이라 추가 호출은 없음 (토큰 증가는 측정해서 기록)
- 방문 안 프레임 중 하나라도 "두 명 이상" 확률이 판정 기준(0.5) 이상이면 여러 명 방문으로 봄
- "여러 명"은 **등급을 올리는 근거가 아니라 위 표의 마지막 칸을 가려내는 조건**으로만 씀. 진열대 근거·행동 근거 점수(결정 006)는 그대로임
- 피로도를 줄이기 위해 **푸시 알림은 높음·중간만** 보내고, 낮음은 목록에만 남김 (5단계 FCM)
- 사람 추적(C)은 회고의 "다음에 바꿀 것"으로 남김

## 한계
- 개수 실험에서 Jev가 칸별 개수를 셀 수 있다고 나오면 "개수를 확인할 수 없음"인 경우가 거의 없어져 이 규칙이 거의 쓰이지 않음. 반대로 개수를 못 세면(handoff 6장: 개수 세기는 Jev 약점) 여러 명 방문 중 결제가 있는 방문은 대부분 낮음이 됨 → 3단계에서 표시 수와 그중 실제 도난 수를 재서 조건을 다시 봄
