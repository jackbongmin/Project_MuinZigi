# [결정] 질문을 Y/N에 따라 분기하지 않고 한 번에 묻고, 도난 판정은 진열대 비교에 맡김

## 상황
- 0단계에서 Jev가 "상품을 가방에 넣음(도난)"과 "자기 폰을 가방에 넣음(정상)"을 사진 한 장으로 가르지 못했음 (N5 오탐 0.84~0.86이 진짜 장면 P2 0.75보다 높음)
- 질문 문구를 고쳐서(v1·v2) 자기 물건 오탐은 없앴지만, 진짜 장면(P2 7초)도 0.5 근처로 같이 내려가 실행마다 잡았다 놓쳤다 함
- 여기서 **"도난이 안 잡히는 건 질문지를 제대로 만들지 않아서가 아닌가?"** 라는 의문이 생김. 구체적인 가설은 두 가지였음

### 가설 1. 질문을 Y/N에 따라 분기하면 더 효율적이다
- "사람이 있나?"가 N이면 나머지 질문은 필요 없음
- "무언가를 넣었나?"가 Y일 때만 "가방? 주머니? 장바구니?"를 물으면 큰 맥락부터 좁혀 가서 효율적일 것

### 가설 2. 질문을 더 세분화하면 도난을 더 잘 잡는다
- 넣은 곳(가방·주머니·옷 속·장바구니)을 따로 물으면 정상(장바구니)과 의심(주머니·옷 속)을 가를 수 있을 것
- "진열대에서 물건이 사라진 상태가 지속되나"를 물으면 넣는 순간이 안 보여도 잡을 수 있을 것

## 선택지
- **A: 질문 분기** (요청 1: 사람? → Y면 요청 2: 행동 질문들 → …)
  - 장점: 답이 N인 뒤의 질문을 생략함. 흐름이 사람의 판단 순서와 비슷함
  - 단점: 단계마다 요청을 새로 보내야 함 → 요청마다 이미지를 다시 보냄. 앞 단계가 틀리면 뒤 질문을 통째로 놓침
- **B: 한 요청에 질문을 모두 넣고, 분기는 프레임 단위로 함** (현재 방식)
  - 장점: 이미지는 한 번만 보냄. 분기는 "사람 없는 프레임은 아예 안 보냄"으로 처리
  - 단점: 필요 없는 질문까지 매번 물음
- **C: 질문 세분화** (넣은 곳 질문 추가, v3)
- **D: 진열대 전후 비교** (손님 방문 전 프레임 vs 후 프레임, 결정 001)

## 실험 (2026-10-29)
- 데이터: AI 생성 영상 7편(P2, P3, N1~N5), 1초당 1장 프레임 + P1 (총 109장)
- **정답은 Jev 호출 전에 정함** (v3 추가 질문, 진열대 비교 모두)
- 같은 실행에서 v0·v1·v2·v3을 같은 프레임에 연달아 보냄. 모델 `jev-1.14.0`, 판정 기준 0.5

### 실험 1. 분기(A) vs 한 번에(B): 토큰 비용
- 요청 하나의 입력 토큰을 측정해서 분해함
  - 질문 4개(v2): 2,803 / 질문 7개(v3): 2,883 → **질문 하나당 약 27토큰**
  - 나머지 약 2,700토큰은 이미지(1280x720)와 고정 지시문 → 비용의 96%가 이미지
- 이 값으로 109장 전체에 분기 방식을 적용했을 때를 계산함 (분기는 실제로 돌리지 않고 측정값으로 계산한 추정)
  - 109장 중 person ≥ 0.5인 프레임: 92장

| 방식 | 요청 수 | 입력 토큰 | 비고 |
|---|---|---|---|
| B: 한 번에 (현재) | 109 | 305,527 | 실측 |
| A: 분기 (사람? → 행동 질문) | 201 | 약 552,000 (**+81%**) | 추정. 사람 있는 프레임은 요청 2번, 응답 시간도 약 2배 (요청당 평균 215ms) |
| B + 프레임 분기 (사람 없는 프레임은 안 보냄) | 92 | 약 258,000 (**-16%**) | 추정. 사람 감지는 Jev 없이 장면 변화로 한다고 가정 |

- 이 데이터는 AI 영상이라 빈 화면이 적음(17장). 실제 녹화본은 대부분 빈 시간이라 프레임 분기의 효과가 훨씬 커짐
- 오답 전파: 이번에는 person 오답이 0개라 분기 때문에 놓친 프레임은 없음. 다만 사람이 화면 가장자리에 조금 걸린 프레임(P2 1·10초)은 정답 자체가 애매했음

### 실험 2. 질문 세분화(C): 넣은 곳 질문 3개 추가 (v3)
| 질문 | 채점 | 일치 | 정답이 "예"인 프레임 | 오탐 |
|---|---|---|---|---|
| into_pocket | 82 | 81 | P2 7초 → **0.29로 놓침** | 0 (최고 0.21) |
| into_clothes | 81 | 81 | 없음 (P3 숨기는 동작은 안 보여서 "?") | 0 (최고 0.38) |
| into_store_basket | 89 | 89 | 없음 (장바구니 장면 없음) | 0 (최고 0.17) |

- 같은 프레임(P2 7초)에서 putting_in_bag은 0.54, into_pocket은 0.29 → **세분화한 질문이 오히려 더 못 잡음**
- 오탐은 없었지만 "예"를 맞혀야 하는 장면이 거의 없어서, 세분화 질문의 쓸모는 이 데이터로는 확인할 수 없음
- 기존 4개 질문의 결과는 v2와 거의 같음 (전체 일치 318 → 317, 노이즈 범위)

### 실험 3. 진열대 전후 비교(D): 영상의 첫 프레임 vs 마지막 프레임
- 질문: "before와 비교해 after에서 사라진 상품이 있나?"(missing), "두 진열대가 같나?"(same)
- full: 화면 전체 / roi: 상품이 놓인 진열대 칸만 잘라냄 (장면마다 좌표를 사람이 정함)

| 장면 | 정답 | missing (full) | missing (roi) |
|---|---|---|---|
| P2 캔을 주머니에 | 사라짐 | **0.94** ✅ | 0.95 ✅ |
| P3 초콜릿을 소매에 | 사라짐 | **0.93** ✅ | 0.97 ✅ |
| N2 캔을 들고 계산대로 | 사라짐 | 0.84 ✅ | 0.94 ✅ |
| N1 보고 다시 놓음 | 없음 | 0.10 ✅ | 0.20 ✅ |
| N3 키오스크 결제 | 없음 | 0.08 ✅ | 0.15 ✅ |
| N4 자기 폰을 꺼냄 | 없음 | 0.26 ✅ | 0.39 ✅ |
| N5 자기 폰을 넣음 | 없음 | **0.58 ❌** | **0.75 ❌** |

- 행동 판단과 같은 장면을 비교하면 차이가 분명함

| 장면 | 행동 판단 (v2 putting_in_bag 최고) | 진열대 비교 (full missing) |
|---|---|---|
| P2 (진짜 도난, 주머니) | 0.53, 기준선 근처 | 0.94 |
| P3 (진짜 도난, 소매) | 0.28, 놓침 | 0.93 |
| N4 (자기 물건) | 0.69, 오탐 | 0.26 |

- **행동이 가려진 P3도 진열대 비교로는 잡힘.** 자기 물건 장면(N4)도 사라진 상품이 없어서 낮게 나옴
- N5 오탐의 원인: 마지막 프레임에서 사람이 진열대 앞에 서서 가림 → 가려진 상품을 "사라짐"으로 봄. 결정 001에서 예상한 약점(비교할 빈 화면이 없을 때)이 실제로 나타남
- N2는 상품이 사라졌지만 계산대로 가져가 결제하는 장면임 → 사라짐만으로는 도난이 아님. 결제 내역(CSV) 대조가 필요한 이유
- roi는 토큰을 70% 줄였지만(5,126 → 1,398~1,782) 정답이 "없음"인 장면의 확률도 같이 올라감(N4 0.26 → 0.39, N5 0.58 → 0.75). 별도 기록: `performance/2026-10-29_진열대_칸_자르기로_토큰_감소.md`

## 결정과 이유
- **B(한 번에 묻기 + 프레임 단위 분기)를 유지함.** 분기(A)는 질문 토큰(약 27)을 아끼려다 이미지 토큰(약 2,700)을 두 번 내게 되어 비용이 약 81% 늘어남. 아낄 곳은 질문이 아니라 프레임임
- **질문 세분화(C)는 지금 판정에 넣지 않음.** 같은 장면에서 오히려 더 못 잡았고, 질문 하나당 비용은 작아서(약 1%) 장바구니 장면이 생기면 다시 시험함
- **도난 판정의 핵심은 진열대 비교(D) + 결제 대조로 둠** (결정 001을 실제 영상으로 확인함)
  - 행동 판단으로 가르지 못한 세 장면(P2 기준선 근처, P3 놓침, N4 오탐)을 진열대 비교는 모두 맞힘
  - 행동 판단은 "누가, 언제" 그리고 점주에게 보여줄 캡처 장면을 고르는 역할로 둠

### 의문에 대한 답
- "질문지를 제대로 만들지 않아서 도난이 안 잡히나?" → **부분적으로만 맞음**
  - 문구 문제는 실제로 있었고, 고쳐서 자기 물건 오탐이 줄었음 (v0 → v2, 성능 기록 참고)
  - 하지만 근본 원인은 **사진 한 장에 "어디서 왔나, 사라졌나, 결제했나"라는 정보가 없다는 것**임. 질문을 분기하거나 세분화해도 모든 질문이 같은 사진 한 장을 봄
  - 필요한 정보는 질문이 아니라 **입력(전후 두 장)과 다른 데이터(결제 내역)** 를 바꿔야 들어옴

## 한계
- AI 생성 영상 7편, 장면마다 1회 측정. 진짜 "넣음" 정답 프레임이 P2 7초 하나뿐임
- 분기 방식의 비용은 실측값으로 계산한 추정이며, 분기를 실제로 돌리지는 않았음
- 진열대 칸 좌표는 사람이 장면마다 정했음 (실서비스에서는 카메라 등록 시 점주가 한 번 지정하는 방식을 가정)
