# [결정] 진열대 전후 비교를 미결제 판정의 근거로 사용

## 상황
- 처음 설계는 "손님이 상품을 가방·주머니에 넣는 장면"을 Jev가 찾으면 의심 장면으로 보는 방식이었음
- 0단계 영상 테스트(P1)에서 문제가 드러남
  - 카메라가 뒤에서 찍어 **가방에 넣는 순간이 어느 프레임에도 보이지 않았음** (1초에 4장으로 촘촘하게 뽑아도 같음)
  - 실제로 훔치려는 사람은 카메라를 피하려고 함. 행동 장면에만 의존하면 가장 중요한 경우를 놓침
- 목표가 "미결제 놓침 0건"이라, 행동이 가려져도 남는 증거가 필요했음

## 선택지
- **A: 행동 판단만 사용** (집음 → 가방에 넣음)
  - 장점: 구현이 단순함. 점주에게 보여줄 캡처 장면이 바로 나옴
  - 단점: 손이 가려지면 놓침. 자기 물건을 가방에 넣는 장면(N5)과 구분이 어려움
- **B: 진열대 전후 비교만 사용** (손님이 들어오기 전 vs 나간 뒤, 사라진 상품 vs 결제 내역)
  - 장점: 동작이 가려져도 "상품이 없어졌다"는 결과가 남음. 자기 물건과 매장 상품을 자연스럽게 구분함
  - 단점: 손님이 연달아 있으면 비교할 빈 화면이 없음. 여러 명이 동시에 있으면 누가 가져갔는지 모름. 진열 정리나 다른 칸에 다시 놓은 경우를 "사라짐"으로 잘못 볼 수 있음
- **C: 둘을 함께 사용**
  - 진열대 비교로 "무엇이 사라졌나"를 판단함
  - 행동 판단으로 "누가, 언제, 어떻게"를 보충하고 캡처 장면을 고름
  - 결제 내역 대조는 Java 코드에서 함

## 결정과 이유
- **C를 선택함**
- 최종 판정 기준은 "진열대에서 사라진 상품 수가 결제된 상품 수보다 많은가"로 둠
  - 넣는 장면은 판정의 필수 조건이 아니라, 의심도를 높이는 증거이자 점주에게 보여줄 캡처 장면 역할을 함
- 행동이 가려져도 놓치지 않는 쪽을 우선함 (목표: 놓침 0건)
- 개수 세기는 Jev의 공식 약점임
  - Jev에게는 "이 칸에서 상품이 사라졌나"(예/아니오)만 물음
  - 개수 비교와 결제 대조는 Java에서 함

## 근거 (0단계 측정, 2026-10-28)
- 자세한 내용: `docs/test-data/2026-10-28_jev_영상_테스트.md`

| 비교 | 정답 | missing | same |
|---|---|---|---|
| 같은 사진 두 장 | 사라짐 없음 | 0.10 | 0.96 |
| P1 0초 vs 19초 | 사라짐 없음 | 0.23 | 0.68 |
| 19초에서 봉지 2개를 지운 사진 | 사라짐 있음 | 0.58 | 0.21 |

- 세 경우 모두 방향은 맞음. P1에서 사라짐을 못 잡은 건 Jev 문제가 아님. AI 생성 영상이 상품을 가져가도 진열대를 그대로 그렸기 때문임 (데이터 문제)
- 다만 사라짐 확률이 0.58로 약함 → 진열대 칸만 잘라 비교하는 방식으로 개선을 측정할 예정
