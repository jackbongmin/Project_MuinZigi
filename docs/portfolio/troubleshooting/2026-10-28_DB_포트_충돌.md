# [트러블슈팅] Docker PostgreSQL이 떠 있는데 Spring이 다른 DB에 접속함

## 현상
- `docker compose`로 PostgreSQL 18 컨테이너를 띄움. `pg_isready`로 확인한 결과 접속을 정상적으로 받고 있었음
- 그런데 Spring Boot 테스트(`contextLoads`)를 실행하면 DB 연결 단계에서 실패함
- 겉으로 보이는 오류는 `Unable to determine Dialect without JDBC metadata`(Hibernate)였음

## 원인 추적 과정
1. **Hibernate Dialect 설정 문제로 의심함**
   - 오류 메시지만 보면 DB 종류(Dialect)를 지정하라는 뜻으로 읽힘
   - 하지만 Spring Boot는 접속에 성공하면 Dialect를 자동으로 판단함
   - 그래서 더 아래쪽의 `Caused by`를 확인함. 진짜 오류는 `PSQLException: 사용자 "mujinjigi"의 password 인증을 실패했습니다`였음 (Windows 콘솔에서 한글이 깨져 보임)
2. **`.env` 비밀번호 오타로 의심함**
   - 컨테이너는 `.env`의 같은 값으로 만들어졌으므로 오타일 가능성은 낮았음
   - 오류 메시지가 **한국어**라는 점이 눈에 띔. 공식 `postgres` Docker 이미지는 기본 언어가 영어라서 한국어로 답하지 않음
   - 그래서 "Docker가 아닌 다른 PostgreSQL이 요청을 받았다"는 가설을 세움
3. **5432 포트를 누가 쓰는지 확인함**
   - `Get-NetTCPConnection -LocalPort 5432`로 확인함. `postgres.exe`(Windows 프로세스)가 `0.0.0.0:5432`, `[::]:5432`를 점유하고 있었음
   - `Get-Service postgresql*`로 확인함. `postgresql-x64-18` 서비스가 자동 시작으로 실행 중이었음

## 진짜 원인
- PC에 직접 설치된 PostgreSQL 18이 부팅할 때마다 5432 포트를 먼저 잡고 있었음
- Docker도 5432에 연결된 것처럼 표시됐지만, `localhost:5432` 요청은 설치된 PostgreSQL이 받았음
- 그 DB에는 `mujinjigi` 계정이 없어서 인증에 실패함

## 해결
- 설치된 PostgreSQL은 다른 용도로 쓸 수 있어서 그대로 두기로 함. 대신 Docker 쪽 PC 포트를 5433으로 바꿈
  - `docker-compose.yml`: `"${DB_PORT:-5433}:5432"`
  - `application.properties`: `jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5433}/${DB_NAME}`
- 접속 주소 전체(`DB_URL`)를 `.env`에 두던 방식을 바꿈. 이제 호스트·포트·DB 이름을 조합해 만듦. 포트를 바꿀 때 한 곳만 고치면 되도록 하기 위함
- 결과: 테스트 통과. 로그에서 `jdbc:postgresql://localhost:5433/mujinjigi`, `Database version: 18.6` 접속을 확인함

## 배운 점
- 스택 트레이스는 맨 위가 아니라 가장 아래쪽의 `Caused by`부터 읽어야 함
- "서버가 떠 있다"와 "내 프로그램이 그 서버에 붙었다"는 다른 문제임. 포트를 점유한 프로세스를 직접 확인해야 함
- 오류 메시지의 언어 같은 사소한 단서가 "누가 응답했는가"를 알려줌
- `${이름:기본값}`(Spring)과 `${이름:-기본값}`(compose)은 빈 값을 다르게 처리함
  - compose의 `:-`는 빈 값이어도 기본값을 씀
  - Spring은 키가 없을 때만 기본값을 쓰고, 빈 값은 그대로 씀
  - 그래서 `.env.example`에서 이 키들은 주석으로 둠
