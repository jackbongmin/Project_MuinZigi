## 핵심 개념
- **방문 나누기 = 긴 녹화본의 시간 줄을 손님 단위로 자르는 것**: 판정(진열대 전후 비교, 결제 대조, 의심 장면)은 손님 단위라 시작·끝 시각이 먼저 있어야 함
- **공백은 "안 보인 프레임 수"가 아니라 "보인 시각의 차이"로 잼**: 활동 구간 밖은 프레임 자체가 없어서, 장 수로 세면 3초 → 20초가 이어져 버림
- **계산과 저장을 나눔**: `VisitSplitter`는 `new`로 만들어 1초 안에 경계값을 확인하고, API 테스트는 저장·응답 코드만 확인함. 둘이 맡은 일이 다름
- **`@Value("${키}")`의 `}`가 빠지면 서버가 아예 안 뜸**: 닫히지 않은 `${...`는 설정값으로 바뀌지 않고 글자 그대로 남아 `double`로 바꾸다 실패함. `new`로 만드는 단위 테스트는 `@Value`를 안 거쳐서 못 잡고, Spring을 띄우는 테스트 28개가 한꺼번에 실패함
- **record 칸 이름 = JSON 칸 이름**: `VisitResponse`의 칸 이름 오타가 그대로 API 응답의 이름이 됨. 화면·앱이 `frameCount`를 찾으면 값이 없게 됨

## 코드 흐름 (방문 나누기)
1. `VisitController.split()` → `VisitService.split(videoId)` (`@Transactional`)
2. 영상 확인(없으면 404) → `findAllWithFrame(videoId, "v2")`로 판단 결과를 시각 순으로 읽음 (없으면 409)
3. 판단마다 `(프레임 시각, person 확률)`만 뽑아 `PersonFrame` 목록을 만듦
4. `VisitSplitter.split()`: 0.5 미만은 건너뜀 → 마지막으로 보인 시각과 5초보다 차이 나면 앞 방문을 닫음 → 반복이 끝나면 남은 방문을 넣음 → `VisitRange` 목록
5. `deleteByVideoId`로 이전 방문을 지우고 `Visit`으로 바꿔 `saveAll` → 201 + 방문 목록

## 리뷰에서 지적된 점
- **`VisitSplitter` 생성자 `@Value("${app.visit.gap-seconds")`에 `}`가 빠짐**: `VisitSplitterTest` 6개는 통과했지만 Spring을 띄우는 테스트 28개가 모두 실패함 (`For input string: "${app.visit.gap-seconds"`). `}`를 넣어 고침
- **`VisitResponse`의 칸 이름 `franeCount`**: API 응답이 `"franeCount": 9`로 나가서 `$[0].frameCount`를 확인하는 테스트가 실패할 상태였음. `frameCount`로 고침
- 그 밖의 코드는 가이드와 같음 (주석 문구만 다름)

## AI 결과를 의심하고 확인한 것
- **방문 나누기가 손님을 사람별로 구분하는지**: "A, B, C가 각자 인식되나, 여러 명이 한 화면에 잡히면 체크되나"라고 물음 → Claude Code가 설계를 다시 보고 사람별 구분이 안 되고 겹치면 하나로 합쳐진다고 인정함. 다른 손님의 결제가 도난을 가리는 경우도 찾음 → 결과: 설계의 구멍이 맞았음. 결정 007로 남김
- **"여러 명이면 모두 확인 필요" 제안**: 그러면 일행이 올 때마다 낮음이 떠서 피로도가 너무 크다고 지적함 → 합쳐져서 실제로 문제가 되는 경우를 다시 나눠 봄 → 결과: 제안이 너무 넓었음. "결제가 도난을 가릴 수 있을 때만"으로 좁혀서 고침
- **가이드 클래스 주석**: "녹화본 안의 방문 하나" 같은 주석이 무슨 클래스인지 안 읽힌다고 지적함 → 결과: 맞았음. 한 문장 + 예시 규칙을 만들고 기존 코드 69개 클래스까지 전부 바꿈

## 스스로 답해볼 질문
1. 방문을 "안 보인 프레임 수"가 아니라 "보인 시각의 차이"로 나눈 이유는 무엇인가. 프레임 수로 세면 어떤 경우에 틀리는가
2. `@Value`의 `}` 하나가 빠졌는데 단위 테스트는 통과하고 Spring 테스트만 실패한 이유는 무엇인가. 단위 테스트와 통합 테스트는 각각 무엇을 잡는가 (면접 질문)
3. 경계값 테스트에서 0.49와 0.5, 차이 5초와 6초를 모두 넣은 이유는 무엇인가 (면접 질문)
4. 판단은 "이미 한 것은 건너뜀"인데 방문 나누기는 "지우고 새로"인 이유는 무엇인가. 지우기와 저장을 한 트랜잭션으로 묶지 않으면 어떤 일이 생기는가
5. 손님 두 명이 방문 하나로 합쳐지면 어떤 미결제를 놓칠 수 있는가. "여러 명이면 모두 표시"하지 않고 조건을 좁힌 이유는 무엇인가
